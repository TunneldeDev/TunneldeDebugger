# 操作与架构

## 预览缩放与布局

预览默认使用“适应窗口”，随展示区大小自动缩放，显示完整场景。预览上方的减号、百分比下拉框和加号可手动缩放（10%–200%）；选择 100% 按原始像素查看，点击“适应窗口”恢复自动缩放。手动放大后，可在预览区域横向和纵向滚动。

缩放仅改变预览的显示比例，不改变场景视口、数据、代次或截图分辨率。右侧的宽度／高度改变真实渲染视口，用于验收响应式布局。标题栏两端的侧栏按钮可收起／展开资源管理器和检查器；检查器默认收起，展开后固定停靠在右侧；窄窗口改为上下分区，不遮挡预览。资源管理器在空间不足时收起，可按需展开。工作台采用 Tunnelde 的石墨色板，场景本身的主题与语言独立设置。

## 记录问题与管理验收

点击场景标题旁的“记录问题”，填写标题和问题描述，选择“有问题／阻塞／待检查／通过”，再点“保存记录”。保存按钮始终位于表单上部；只有服务完成写盘后才显示“记录已保存”。复现步骤、预期结果和检查清单可以展开填写。目标无法启动或场景加载失败时，仍可保存问题和阻塞记录；“通过”要求匹配当前就绪场景与源码。

“截图”或表单内“截取当前界面”保留当前输入、弹窗、选择和内部容器的横向／纵向滚动位置，不会重新启动初始场景。浏览器使用当前文档生成图片，复杂图形或浏览器专属效果可能与原生截图不同；需要精确像素证据时可上传系统截图。原生模式继续按目标窗口采集。也可上传 PNG/JPEG/WebP、在表单中粘贴图片，或把图片拖进附件区域。点击“标注”拖出带编号的红框，再保存标注；附件可预览、下载或移除。

未提交的草稿（包括附件引用）按场景、参数、目标和源码版本保存在当前浏览器；切换场景、切换标签或刷新后可继续编辑。草稿不等于已经提交的验收记录，换浏览器或清理浏览器存储不会保留草稿。截图和已保存的记录存放于调试器本地数据目录。

验收记录支持搜索、查看全部场景、编辑标题／描述／结论／优先级／附件，以及删除。删除立即移入“回收站”，可在回收站搜索并恢复任意已删除记录，刷新后仍保留。删除采用软删除，不会物理清除图片，导出报告只包含未删除记录。编辑保留原始场景参数和源码身份；多窗口同时编辑同一记录时，过期修改被拒绝，避免覆盖新内容。保存失败会显示原因并保留表单。

## 项目配置与桌面操作

顶部 **项目配置** 提供本地 Tunnelde 绝对路径、服务端口、Cargo 参数、应用参数和环境变量。展开“当前接口与存储位置”查看 API、渲染器、原生前端、数据目录和配置文件。参数为 JSON 数组、环境变量为 JSON 对象，直接传给子进程。配置保存在本地 `project.json`。停止所有实例与测试后可切换项目；保存路径立即重建场景服务并清除旧测试发现缓存。没有 `src/debugger/index.tsx` 的普通项目，需要先在隔离副本应用 `integration/tunnelde.patch` 并安装依赖，Debugger 不会自动修改所选项目。

修改服务端口后需重启；渲染器、原生前端、HMR 使用端口 +1、+2、+3，均限定 loopback。`pnpm desktop --port 4880 --target /absolute/Tunnelde --data /absolute/debug-data` 使用匹配的 URL 与 CSP 启动独立桌面服务，命令行参数优先于已保存配置。Windows 使用跨平台子进程启动器，取消时清理整棵进程树。GitHub Actions 检查 macOS、Windows、Linux 的工作台及桌面源码；非 macOS 原生截图仍需上传系统截图，各平台实际验收状态单独记录。

检查器默认关闭，打开后固定停靠；窄窗口上下分区。预览会按剩余空间自动适应，场景视口和交互状态保持不变。检查器标题栏始终提供关闭按钮，内容独立滚动。拖动 iframe 顶栏，或启用“拖动画布”后在画布上拖动，可移动展示位置；退出拖动模式继续操作软件，“居中画布”恢复原点与适应窗口。点击截图在应用内预览，支持原始尺寸、缩放和前后图片，Escape 关闭。下拉框使用工作台石墨主题，支持键盘与 Escape。

结论与 P 等级独立保存：P0 阻断、P1 高、P2 中、P3 低、P4 建议；结论包含待检查、检查中、有问题、阻塞、待复测、已修复、通过、不适用、重复问题、暂不处理。优先级不会自动授予通过。日志安全渲染 ANSI 标准、亮色、256 色及 RGB，其他终端控制码不会显示为乱码。

## 数据流

工作台 React UI → loopback Node 服务 → 测试运行器或受控原生协议。浏览器场景由另一端口的 iframe 加载主仓库 `src/debugger/index.tsx`，直接导入生产 AppShell、页面、控件、样式和 Services。iframe 每次切换重新创建，localStorage/sessionStorage 在场景文档中替换为内存存储。

开发契约位于 `shared/protocol.ts`：`ScenarioDefinition` 声明预设、目标、准备步骤、清单和测试关联；`DebugTarget` 提供发现、准备、应用、快照和释放；`TestRunnerAdapter` 统一发现、运行、取消信号和事件。`server/native-target.ts` 为原生目标实现该契约。

## 场景与扩展

`shared/scenarios.ts` 是覆盖登记表。主题、语言、尺寸和种子是独立参数；预设不适用时显示 N/A 原因。边界预设生成至少 1,000 条数据，最多 10,000 条，附带长名称、多语言和多层分组。部分固定控件只有少量内容，数据量不会人为复制控件。

模拟适配器提供主机、设置、文件、转发和插件等可变数据。未实现的调用明确抛出 `Unsupported fixture operation`，不会返回伪造的成功。终端模拟只回显输入；真实服务任务才会连接 SSH 服务。生产声明式插件渲染器使用已登记的合成插件。

`examples/plugin-scenarios.ts` 演示代码注册扩展：审核后在共享场景模块中调用 `registerScenarioExtension`，工作台和渲染器一起加载。扩展只能引用已知界面并限定为浏览器目标；协议不接收脚本、组件路径或任意 invoke。

## 原生隔离与生命周期

目标必须同时启用 Cargo `debugger`、debug 构建、前端 DEV 开关、运行时开关、独立应用标识和匹配 runId 的配置目录标记。普通构建不注册开发命令。凭据沿用主仓库按应用标识划分的命名空间；调试标识为 `dev.tunnelde.debugtarget`。Node 为每个真实服务任务创建新 UUID 数据及插件目录。

原生端点只监听 `127.0.0.1`，描述文件使用独立随机令牌、协议版本和 runId。请求有容量、认证、超时及代次检查；命令仅允许登记场景、参数和操作。服务的前端请求保留 Host/Origin/JSON 检查。

场景“接受”不等于“就绪”：服务等待组件提交后的确认。模拟切换重载文档，销毁订阅、缓存和内存存储；真实服务重置重启实例并使用新目录。原生小窗沿用生产窗口所有权与代次协议；返回操作由实际拥有面板的小窗执行。

受控 SSH/SFTP 服务只接受合成用户名和口令，监听 loopback，SFTP 限定到临时文件根目录，拒绝路径穿越和符号链接。终端是受控回显服务，不运行系统 shell。初始本地文件面板和远端文件面板均显式打开验收目录。正常生产文件界面的用户导航能力仍然存在。

## 测试管理

按运行器、目录、文件和用例展开。Vitest 使用现有配置和结构化 reporter；Rust 编译并从实际测试程序获取列表，单项执行使用 `--exact`；Node 使用原生测试事件，动态子用例运行后加入树；Playwright 复用同一场景登记表。原生任务单独列出，不由浏览器结果替代。

“运行已发现全部”只执行已经登记并发现的集合，未发现的运行器不会自动算作通过。Rust ignored 测试单独标记；运行时 skipped/todo 不计为用例通过。外部环境要求沿用测试本身的 skip/ignored，无法静态判断的要求在运行错误和输出中呈现。每个目标由一个队列串行执行；运行器内部保持原并发。

取消时先终止整个子进程组，再强制清理；服务重启将未完成任务标记为中断，已有记录保留。Node 测试文件可以含动态用例，发现阶段仅执行文件扫描，不提前运行测试。

## 记录与证据

`.tunnelde-debugger/runs.json`、`acceptance.json` 和 `artifacts/` 存储本地记录；写入采用临时文件及原子重命名。源码身份包含绝对路径、Git revision、工作区 diff/未跟踪文件内容指纹和协议版本。通过结论要求匹配就绪场景与参数；源码变化后需重新加载。

截图按 macOS 目标 NSWindow 编号采集，先聚焦对应窗口。自动原生任务分别采集小窗和返回后的主窗；截图失败保留明确原因。JSON 报告保存产物引用，图片文件保留在本地 artifacts 目录，分享报告时需同时提供所选图片。

手工结论由验收人填写；自动测试中的记录持久化检查使用带 `Playwright acceptance record` 备注的样例记录，不代表人工验收完成。
